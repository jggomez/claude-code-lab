El Espejismo de la Velocidad

!
La Ilusión de la Rapidez

Generar código con IA es instantáneo, pero el razonamiento y la auditoría humana se mantienen en un ancho de banda constante.

  • Escribir diffs sintácticos es trivial y barato
  • El cuello de botella real es la comprensión humana
  • Más líneas por minuto no equivale a más valor
×
El Riesgo del Falso Rigor

Aceptar cambios solo porque compilan o pasan tests superficiales no es programar con rigor: es acumular deuda invisible.

  • El compilador no sabe qué quería el usuario
  • Aprobación masiva por fatiga de revisión
  • Desconexión progresiva del equipo con el código
Riesgos Críticos · Costos Ocultos
Riesgos Críticos

Las Tres Deudas Invisibles del Vibe Coding

01
Comprehension Debt
Addy Osmani (2026)

La brecha entre el código acumulado y lo que el equipo entiende. Si nadie entiende el software desde primeros principios, nadie lo arreglará cuando falle en producción.

02
Intent Debt
Pérdida del "Porqué"

Si no existe especificación explícita de negocio, el agente toma decisiones probabilísticas. El sistema muta hacia soluciones ad-hoc que nadie solicitó conscientemente.

03
Review Debt
Fatiga de Auditoría

La saturación de diffs enormes genera aprobación ritual. Los ingenieros aceptan PRs sin auditar contratos, degradando los estándares de seguridad y mantenibilidad.

Escalabilidad de Equipos Agénticos
Límites de Escala
10 ≠ 10×

La Tasa de Orquestación:
Coordinar supera a programar

Lanzar diez agentes concurrentes no multiplica la velocidad por diez.

Crear tareas es barato; verificar, validar contratos, resolver colisiones entre archivos y mergear ramas concurrentes es sumamente costoso. La saturación aparece en el momento en que el tiempo de arbitraje y coordinación supera al tiempo de desarrollo directo.

Gobernanza y Reglas Deterministas
Gobernanza

El Principio del Trinquete (Ratchet)

Ante cada fallo o alucinación del agente, se programa una regla determinista para que ese error sea físicamente imposible de repetir.

Doc
Instrucciones Pasivas (CLAUDE.md)
  • Documento vivo curado por humanos con cada incidente
  • Orienta el modelo antes de generar código
  • Límite: El modelo puede ignorarlas si satura el contexto
Hook
Sensores Activos (Hooks & Pre-commit)
  • Scripts en el arnés ejecutados en eventos clave
  • Bloquea commits y rechaza diffs inválidos determinísticamente
  • Ventaja: No depende de la "voluntad" del LLM

Modelos de Operación con IA
Filosofía

Dark Factory vs. Lit Factory

×
Dark Factory (Fábrica Oscura)
  • Control: Totalmente delegado; nadie revisa los diffs generados.
  • Sensor: Asume falsamente que si compila, la lógica está bien.
  • Riesgo Crítico: Deuda de comprensión absoluta y código inauditado.
  • Resultado: Pérdida total del control del sistema ante incidentes.
✓
Lit Factory (Fábrica Iluminada)
  • Control: Prioridad del humano en la arquitectura y especificación.
  • Sensor: Pruebas de contrato + oráculo de verificación deliberado.
  • Beneficio: Máxima velocidad agéntica preservando el modelo mental.
  • Resultado: Software escalable, limpio y comprendido desde el día 1.

Bucle Interno

  • Definir el problema de negocio y casos de uso
  • Diseñar contratos de interfaces y arquitectura limpia
  • Crear la suite de verificación y oráculos de prueba
  • Auditar y dar el visto bueno final para producción
Spec-Driven Development · Google + Claude Code
Metodología SDD

Spec-Driven Development con Conductor

"Medir dos veces, programar una." Transforma a Claude Code en un ejecutor disciplinado.

1
Context Setup
/conductor:conductor-setup

Audita el repositorio y define la verdad única: product.md, tech-stack.md y workflow.md.

2
Spec & Plan
/conductor:conductor-new-track

Define el requerimiento en spec.md y un desglose atómico en plan.md por fases verificables antes de codificar.

3
Implement Loop
/conductor:conductor-implement

Claude Code ejecuta tarea por tarea, actualizando el progreso y validando contra el plan sin desviaciones.

Fases de Madurez en Adopción Agéntica

1
Calibración

Formar el modelo mental previo, acotar el alcance y limitar el trabajo en progreso (WIP) a tareas atómicas.

Scaffolding

Orquestación
